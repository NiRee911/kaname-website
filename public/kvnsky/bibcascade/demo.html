levers, and what is not a pattern

Escapes travel with unfinished testing

CORRELATION - sprints ending with more than 2 items in Test Blocked leak at 41.2 %; the rest at 13.0 %. Three times the rate, and not a cause: unfinished testing may let defects through, or the same pressure may produce both. This run tested neither direction.

Listed so nobody finds it later and thinks the run missed it. It did not - it declined to report it. At eight it becomes a finding.

The failure mode of this kind of tool is not missing things. It is producing confident clusters that are not there, and being believed.

Human decision. One lever is proposed, with the test that would kill it. The tool does not adopt it.

what this run could not answer

22 defects have no usable trail - no transitions, no environment. Counted as UNKNOWN, excluded from every percentage, never distributed into the nearest phase. That is 5.2 % of the record.

The headline 72.7 % is computed over the 403 that could be placed. Counting the 22 as well, the true figure sits between 68.9 % and 74.1 %. Both are correct; they answer different questions.

Not in the record at all

Severity. Every escape counts the same here. One customer-facing data error and one cosmetic misalignment are the same row, which is certainly wrong and cannot be fixed without a severity field that is used consistently.

Cost. Nothing prices a defect by the phase it was caught in - so "shift left" cannot be argued from this data, even where it is obviously right.

What was prevented. The record holds defects that were found. It is silent about the ones a review caught before anything was written down, which is exactly the work this would most want to credit.
